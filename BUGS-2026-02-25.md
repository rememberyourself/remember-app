## Bug 1: Read-state resets after navigation (CRITICAL)

**Where:** Client Dashboard (e.g. COA login)  
**Reproduction:**
1. Client opens dashboard → sees coach's video response with red dot (NEW)
2. Client clicks/watches the video
3. Red dot disappears (local state `setHasNewResponse(false)` works)
4. Client navigates to `/checkin` or `/history`
5. Client returns to `/dashboard`
6. **BUG:** Red dot is back. Video shows as "unwatched" again.

**Root Cause Analysis (3 hypotheses, investigate ALL):**

### Hypothesis A: Service Worker serving stale JavaScript
The deploy was `remember-v14` cache, but the user's browser might still have the old SW active serving cached old JS. Even with `skipWaiting()`, the first load after deploy serves from old cache. The user needs to reload TWICE for the new SW to take effect.

**Verify:** Check if the deployed JS actually contains the new `seenResponseTimestampRef` logic. Add a `console.log('[Version] remember-app v14')` at the top of `ClientDashboard.jsx` and in `App.jsx`.

### Hypothesis B: `markResponsesSeen()` silently fails
In `api.js`, `markResponsesSeen()` has `.catch(() => {})` which swallows ALL errors:
```javascript
await supabase.from('users').update({ last_seen: now }).eq('id', clientId).catch(() => {});
```
If the Supabase update fails (RLS, network, auth token expired), we never know. The `last_seen` column doesn't update, so `getLatestCoachResponse()` always returns `hasNewResponse: true`.

**Fix:** Add proper error logging. NEVER silently swallow errors on critical writes.

### Hypothesis C: Race condition — DB write not completed before remount
In `handleMarkSeen()`, `markResponsesSeen(user.id)` is called WITHOUT `await`:
```javascript
const handleMarkSeen = useCallback(() => {
  if (hasNewResponse) {
    seenResponseTimestampRef.current = responseTimestamp;
    markResponsesSeen(user.id);  // ← NOT awaited!
    setHasNewResponse(false);
  }
}, ...);
```
If the user navigates away before the HTTP request completes, the DB write might not finish. On remount, `seenResponseTimestampRef` is reset to `null`, and the DB still has the old `last_seen` → red dot returns.

**Fix:** Make `handleMarkSeen` async, await the DB write, and use sessionStorage as immediate backup.

**Oliver's words:** "Patches die kommen erst nachdem man das App geöffnet hat und nicht vorher. Ich habe jetzt auch eine Weile gewartet."

**Where:** Both Client + Coach, likely iOS PWA
**Problem:** Push notifications don't arrive on the device when the app is closed. They only appear (as badge count updates) when the user opens the app.

**Possible causes:**
1. Push subscription not saved to DB correctly (check `users.resources.push_subscriptions`)
2. `send-push.mjs` failing silently when called from `process-reply.mjs`
3. iOS PWA push limitations (iOS requires explicit user gesture to enable push + the subscription can expire)
4. The SW push handler might not fire when the app is fully backgrounded on iOS

**Investigation:**
- Add more logging to `send-push.mjs` and `process-reply.mjs`
- Verify the user has a valid subscription in the DB
- Test by sending a push directly via the API endpoint

## Fix Plan (for Cody)

### Step 1: Fix `markResponsesSeen` in `api.js`
```javascript
export async function markResponsesSeen(clientId) {
  const now = new Date().toISOString();
  const { error } = await supabase
    .from('users')
    .update({ last_seen: now })
    .eq('id', clientId);
  
  if (error) {
    console.error('[markResponsesSeen] DB update FAILED:', error.message);
    // Don't swallow — throw or return false so caller knows
    return false;
  }
  
  console.log('[markResponsesSeen] ✅ last_seen updated to', now);
  
  if ('clearAppBadge' in navigator) {
    navigator.clearAppBadge().catch(() => {});
  }
  return true;
}
```

### Step 2: Fix `handleMarkSeen` in `ClientDashboard.jsx`
```javascript
const handleMarkSeen = useCallback(async () => {
  if (hasNewResponse) {
    const responseTimestamp = latestResponse?.coachResponse?.timestamp;
    // 1. Optimistic local update
    seenResponseTimestampRef.current = responseTimestamp;
    setHasNewResponse(false);
    
    // 2. SessionStorage backup (survives SPA navigation)
    if (responseTimestamp) {
      sessionStorage.setItem('seen_response_ts', responseTimestamp);
    }
    
    // 3. Persist to DB (await it!)
    const success = await markResponsesSeen(user.id);
    if (!success) {
      console.error('[handleMarkSeen] DB write failed, sessionStorage has backup');
    }
  }
}, [hasNewResponse, latestResponse, user.id]);
```

And in `loadData`, also check sessionStorage:
```javascript
getLatestCoachResponse(user.id).then(data => {
  setLatestResponse(data);
  const responseTimestamp = data?.coachResponse?.timestamp;
  const seenInSession = sessionStorage.getItem('seen_response_ts');
  const isNew = data?.hasNewResponse 
    && responseTimestamp !== seenResponseTimestampRef.current
    && responseTimestamp !== seenInSession;
  setHasNewResponse(!!isNew);
}).catch(() => {});
```
